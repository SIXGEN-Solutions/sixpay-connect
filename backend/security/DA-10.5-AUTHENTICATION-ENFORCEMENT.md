# DA-10.5 — Authentication enforcement

## Decision

A valid LOCAL username/password authenticates the SIXPAY identity even when the
credential is expired or marked `mustChangePassword`.

The session is therefore not rejected with HTTP 401. It becomes a restricted
authenticated session.

## State machine

```text
LOCAL username/password
        |
        +-- invalid --> authentication failure
        |
        +-- valid
              |
              v
       credential state
        /      |       \
     normal  expired  must-change
       |        \       /
       v         \     /
 normal session   restricted session
                         |
                         v
                  only:
                  GET  /api/v1/auth/me
                  POST /api/v1/auth/logout
                  POST /api/v1/auth/password/change
```

## OIDC

OIDC is explicitly excluded.

`AuthenticatedUser` retains a compatibility three-argument constructor whose
`passwordChangeRequired` value is false. OIDC authentication therefore never
enters the LOCAL password-lifecycle restriction.

## Session response

Authenticated responses now include:

```json
{
  "authenticated": true,
  "authenticationMethod": "LOCAL",
  "passwordChangeRequired": true
}
```

The existing `authenticationMethod` name is retained instead of introducing a
parallel `authenticationType` field, preserving the DA-8 contract.

## Enforcement

`RestrictedLocalSessionFilter` runs inside the Spring Security chain after
`ExceptionTranslationFilter`.

When the LOCAL session is restricted it denies all routes except the three
password-remediation/session routes.

The principal keeps its normal roles and permissions. Authorization is not
mutated to simulate restriction; restriction is a separate credential/session
state.

## Successful password change

After `ChangeLocalPasswordUseCase` succeeds:

1. the persisted credential has already transitioned to normal;
2. `SpringSecuritySessionManager.completeLocalPasswordChange(...)` replaces the
   in-session principal with the same identity/authorities and
   `passwordChangeRequired=false`;
3. the restriction session attribute is cleared.

No logout/login cycle is required.

## Validation

From `backend/`:

```bash
mvn -pl security -am \
  -Dtest=LocalAuthenticationServiceTest,RestrictedLocalSessionFilterTest,LocalPasswordControllerTest \
  test

mvn -pl security -am test
mvn clean package
```

