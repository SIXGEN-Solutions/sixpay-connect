# DA-10.4 — Change/reset use cases

## Goal

Keep user-owned LOCAL password change and administrative reset as two distinct
workflows.

## User password change

Endpoint:

```http
POST /api/v1/auth/password/change
Content-Type: application/json
```

Request:

```json
{
  "currentPassword": "...",
  "newPassword": "..."
}
```

The caller must already have an authenticated SIXPAY session.

Flow:

```text
Authenticated SIXPAY user
        ↓
load + lock current LOCAL credential/history
        ↓
verify currentPassword against current BCrypt hash
        ↓
PasswordPolicy.validate(newPassword)
        ↓
compare newPassword with current + N historical hashes
        ↓
archive previous current hash
        ↓
replace credential as user-owned change
        ↓
mustChangePassword = false
passwordChangedAt = now
expiresAt = now + expirationDays
        ↓
PASSWORD_CHANGED audit
```

Success returns:

```http
204 No Content
```

## Administrative reset

The existing administration endpoint remains the owner of password reset.

Its flow stays deliberately different:

```text
ADMIN
        ↓
PasswordPolicy.validate(temporaryPassword)
        ↓
anti-reuse check
        ↓
archive previous current hash
        ↓
reset credential
        ↓
mustChangePassword = true
passwordChangedAt = null
expiresAt = null
        ↓
PASSWORD_RESET audit
```

The existing `SecurityUserAdministrationService.resetLocalPassword(...)` and
`LocalAuthenticationUserJpaEntity.resetPassword(...)` remain the reset path.

## Separation

```text
User change
/api/v1/auth/password/change
ChangeLocalPasswordUseCase
PASSWORD_CHANGED
mustChangePassword=false
normal expiration starts

Administrative reset
/internal/api/v1/administration/users/{id}/password/reset
SecurityUserAdministrationUseCase
PASSWORD_RESET
mustChangePassword=true
temporary credential
```

No administrative reset behavior is moved into the authentication controller.

## Validation

From `backend/`:

```bash
mvn -pl security -am \
  -Dtest=LocalPasswordChangeServiceTest,LocalPasswordControllerTest \
  test

mvn -pl security -am test
mvn clean package
```

Manual user-change request requires the authenticated session cookie and the
CSRF token/header already used by the frontend session flow.
