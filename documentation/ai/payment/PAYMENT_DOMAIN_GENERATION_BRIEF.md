## 2. Aggregate Root

`Payment` is the sole write Aggregate Root for one logical TRESOR PAY payment
intention.

Creation and reconstitution are distinct. Aggregate mutation uses named
operations, performs no network call and registers domain events only after
successful mutation.

## 3. Identifier catalogue

| `PaymentRequestIdentity` | Composite of key, fingerprint and correlation |

## 4. Financial and account Value Objects

- shared-kernel `Money` is reused unchanged;
- Payment and allocation amounts must be positive;
- all allocations use the Payment currency;
- allocation sum equals requested amount;
- bank currency support is a policy check;
- debtor account is represented by protected token, masked display and keyed
  binding fingerprint;
- clear account data is forbidden;
- Treasury account is resolved only from protected bank configuration;
- inbound beneficiary data cannot create or override CUT configuration.

## 5. BankPostingReference

One principal posting reference is mandatory after confirmed posting.

Debit and CUT leg references are optional. Command idempotency identity and bank
posting identity remain distinct. Original posting reference survives reversal.

## 6. PaymentFailure

Payment stores one optional current relevant structured failure:

```text

failureCategory
failureStage

safeMessage
occurredAt
externalSystem?
```

Categories:

```text

UNCERTAIN_EXTERNAL_OUTCOME
SECURITY_REJECTION
INTEGRATION_CONFLICT
TREASURY_RECONCILIATION_FAILURE
```

Full failure history belongs to append-only audit/reporting.
